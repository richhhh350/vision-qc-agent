# v2 CPU 研究版：使用与复现

v2 包含深度检测、原图定位、风险守门、人工像素反馈、二级分割、真实池主动学习和版本回滚。它是可审查的研究系统；二级结果只供人工参考，不能凭缺陷概率或看板按钮开启自动放行。

## 1. 环境与数据

本机测试环境是 Windows 11 / Python 3.14；`.venv-v2` 沿用了已有基础包，`pip check` 已通过。`requirements-v2-tested.txt` 保存 107 个实际依赖版本，不把当前环境误称为全新隔离安装验证。新机器的安装脚本默认创建隔离 venv。Linux 深度 CI 和 Docker 配置已写入，但需要真实运行后才算通过。

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup-v2.ps1
.\.venv-v2\Scripts\python.exe scripts/download_ksdd2.py
.\.venv-v2\Scripts\python.exe scripts/import_dataset.py --kind ksdd2 --root data/public/ksdd2/dataset --category ksdd2 --output data/ksdd2-official.csv
.\.venv-v2\Scripts\python.exe scripts/prepare_v2_data.py --source data/ksdd2-official.csv --output data/ksdd2-v2.csv
.\.venv-v2\Scripts\python.exe scripts/download_v2_teacher.py
```

已存在的 manifest / 模型输出目录不会覆盖；继续本机实验时直接使用已有文件。PatchCore 首次加载 `timm/resnet18.a1_in1k` 权重，需要联网，缓存位于 `data/pretrained/huggingface`。EfficientAD 教师来自 Anomalib 官方 Release，下载脚本保存 SHA-256 与来源。数据许可与引用见 [第三方说明](第三方说明.md)。

KSDD2 原训练部分固定拆为 train / dev / prob_fit / calibration / acceptance / pool，官方 test 保留全部 1,004 张。dev 用于选模；acceptance 用于研究风险测量，只有 50 个缺陷。它不具备独立产线采样证明。相同内容跨编码也不能充当新证据；概率拟合、校准、验收要求每个 group 一张图，重复视角必须先制定工件级聚合协议。

## 2. 训练、评测与服务

```powershell
.\.venv-v2\Scripts\python.exe scripts/v2.py train --manifest data/ksdd2-v2.csv --output runs/my-patchcore --config configs/v2/patchcore-letterbox256.json
.\.venv-v2\Scripts\python.exe scripts/v2.py evaluate --run runs/my-patchcore --manifest data/ksdd2-v2.csv --split dev
.\.venv-v2\Scripts\python.exe scripts/v2.py evaluate --run runs/my-patchcore --manifest data/ksdd2-v2.csv --split test
.\.venv-v2\Scripts\python.exe scripts/v2.py train --manifest data/ksdd2-v2.csv --output runs/my-efficientad --config configs/v2/efficientad-cpu.json
powershell -ExecutionPolicy Bypass -File scripts/start.ps1 -V2 -Run runs/my-patchcore -State runs/state-v2
```

打开本地 `http://127.0.0.1:8501`；API 文档在 `http://127.0.0.1:8000/docs`。本机交付的完整演示包是 `runs/v2-review-balanced`，来自开发集选中的 256 等比例 PatchCore，加上固定的 random / seed 17 / 40 标签、200 步均衡采样 U-Net。这个二级模型的效果仍受标注预算限制，用于展示反馈链路，不作为自动决策准确率提升证据。

输出包含原图坐标热力图、框、分数、校准 p 值、原始路由、实际路由、漂移原因、分阶段耗时及可选二级参考分数。随机抽检在完整 v2 策略内执行；证书过期后，即使重复上传曾放行的同一图像，也重新执行守门，不能重放缓存放行。

EfficientAD 使用官方教师/学生/自编码器网络，300 步 CPU 预算训练，省略 ImageNet 外部惩罚项；归一化统计仅来自正常训练数据及其内部留出。它是明确记录的消融配置，不是论文配方复现。

## 3. 人工反馈和候选训练

1. 在复核队列保存正常/缺陷结论。
2. 缺陷样本上传与原图同尺寸的二值掩膜（非零为缺陷）；可记录像素标注秒数。掩膜绑定标签修订号，修正标签后旧掩膜失效。
3. 在主动学习页点击“训练新候选模型”。后台返回任务 ID，状态为 running / completed / failed / cancelled / interrupted；可以取消，失败原因在日志中。
4. 候选不会覆盖当前模型，不会自动提升；完整策略更新后旧证书失效。

命令行等价入口：

```powershell
.\.venv-v2\Scripts\python.exe scripts/v2.py retrain --run runs/v2-review-balanced --state runs/state-v2 --output runs/candidate-01 --steps 120
```

只有正常反馈进入一级正常训练集；带当前掩膜的缺陷反馈进入 U-Net。历史校准、验收、测试图片不能伪装成新反馈。若已用于训练的反馈后来被纠正，自动候选训练会拒绝继续，要求先构建经审计的纠正数据清单，避免旧错误标签悄悄留在模型中。

## 4. 新证据、注册与回滚

```powershell
.\.venv-v2\Scripts\python.exe scripts/v2.py recalibrate --run runs/candidate-01 --manifest data/fresh-evidence.csv --output runs/calibrated-01
.\.venv-v2\Scripts\python.exe scripts/v2.py registry register --run runs/calibrated-01 --directory runs/registry
.\.venv-v2\Scripts\python.exe scripts/v2.py registry list --directory runs/registry
.\.venv-v2\Scripts\python.exe scripts/v2.py registry activate --version <输出的版本号> --directory runs/registry
.\.venv-v2\Scripts\python.exe scripts/v2.py registry rollback --directory runs/registry
```

`fresh-evidence.csv` 仅含新的 prob_fit（可选）、calibration、acceptance。模型权重保持冻结；先写完整策略，再做验收。同一模型父目录的 `acceptance-usage.sqlite` 在评分前登记证据使用，失败尝试也不释放这批数据。跨目录复制、人工修改数据库及外部生产采样的独立性仍需操作流程保障；本地哈希不是防恶意伪造的数字签名。

只有确实具有新鲜、代表性、独立产线数据时才使用 `--independent-production-sampling` 作明确采样声明。它不跳过统计条件：95% 漏检上界须 ≤1%，正常自动误报率须 ≤10%，类别/完整策略/证据哈希和有效期都必须匹配。缺少声明、样本不够、证书错误或过期都关闭自动放行。二级目前始终只给建议。

注册表允许“仅复核模式”模型进入 active；`activate --require-release` 则严格要求有效放行证书。服务启动时可设置 `QC_REGISTRY_DIR=runs/registry` 读取 active 指针；切换后需显式重启服务，未实现热更新。

## 5. 复现实验与 ONNX

```powershell
.\.venv-v2\Scripts\python.exe scripts/run_v2_matrix.py --manifest data/ksdd2-v2.csv --output runs/my-geometry
.\.venv-v2\Scripts\python.exe scripts/v2.py learn --run runs/v2-patchcore --manifest data/ksdd2-v2.csv --output runs/my-learning --budgets 10 20 40 --seeds 17 42 2026 --steps 200
.\.venv-v2\Scripts\python.exe scripts/v2.py export --run runs/my-patchcore --manifest data/ksdd2-v2.csv
.\.venv-v2\Scripts\python.exe scripts/benchmark_v2_http.py --run runs/v2-review-balanced --manifest data/ksdd2-v2.csv --output runs/my-http
```

学习实验固定一级模型，比较同预算监督 U-Net 与“一级路由 + 二级人工建议”；自动路由不被二级更改。每轮在读取 oracle 标签前保存选样记录。非随机策略含 10% 随机探索分支，记录逐次条件抽样概率（不是整个批次的边际入选概率）。图像标签计入既有 train/prob_fit/calibration/acceptance 成本，像素掩膜单独计数；没有真实计时的数据明确记为 null。用于开发评估的标签成本也须在完整项目成本中单独审视。

ONNX 固定单 tile 输入、RGB float32 [0,1]，归一化内嵌；外围沿用同一几何恢复。32 张开发集样本含阈值附近样本，核验分数、原图热力图、嵌入与原始路由，记录容差与翻转。`OnnxDetector` 可用于候选推理；导出通过不会将 PyTorch 证书授予另一个运行时，也不会自动切换生产服务。

HTTP 压测预热 10 次后测 200 次，batch=1、单请求并发，包含 multipart、解码、推理、叠图、SQLite 与 JSON 返回。进程 RSS 是逐请求采样峰值，不等同于操作系统精确峰值；准确性评测中的延迟不含 HTTP，且训练并发时不用于正式性能预算判断。

## 6. 测试与交付边界

```powershell
$env:QC_RUN_DEEP_TESTS='1'
.\.venv-v2\Scripts\python.exe -m pytest -q
.\.venv-v2\Scripts\python.exe -m pip check
```

基础 CI 可跳过深度依赖；单独 deep-contract job 检查两个后端的离线契约。`Dockerfile.v2` 提供深度服务构建入口；本机没有 Docker，容器构建尚未验证。VLM、特征空间漂移监测、MVTec/VisA 全类矩阵、多机部署与真实产线验收是后续范围，不能列作本次已完成项。
