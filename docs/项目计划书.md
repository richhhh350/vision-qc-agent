# 视觉质检 Agent：可校准的异常检测与人工反馈闭环

版本：2026-10-13。首版定位为 Windows / CPU 本地研究原型。按最终方案，主评测直接使用公开数据集，合成数据仅用于流程回归测试；真实产线结论仍须独立验收。

## 1. 项目目标与可交付成果

研究问题是：在缺陷被自动放行的风险可控时，能降低多少人工复核工作量？出现新产品或新缺陷后，恢复目标性能需要多少新增标注？

Agent 的决策空间包含放行、报警、人工复核、抽检、选样和生成候选版本。依据是模型分数、校准预测集合、产品类别、漂移信号和独立验证结果。每次决策保留模型版本、理由及人工反馈，形成可以审计的闭环。

首版交付包括：可运行 CPU 检测器、FastAPI 服务、中文 Streamlit 看板、SQLite 复核队列、三种主动学习策略、候选模型重训练、独立数据重新校准、指标与实验脚本、ONNX 数值与延迟对比、Docker 配置及自动化测试。

## 2. 业务指标的精确定义

设缺陷标签为 Y=1，决策 a∈{pass, alarm, review}。

- 自动放行漏检率：P(a=pass | Y=1)。分母是全部真实缺陷。
- 人工复核率：P(a=review)。线上的随机抽检计入复核成本。
- 自动报警误报率：P(a=alarm | Y=0)。人工复核并不自动算作报警。
- 自动处理覆盖率：P(a≠review)。与 conformal 预测集合覆盖率分开命名。
- 总流程漏检：自动放行漏检 + 人工误判带来的漏检。原型只保证记录前者，不能假设人工永远正确。

主目标：在预先设定风险阈值 ε 下，最小化复核率；同时报告报警成本和实际缺陷基率。实验中的 50% 缺陷比例不能直接代表低缺陷率产线的人工成本。成本估计应按目标产线基率重加权。

## 3. 校准与保证：必须区分的三件事

### 3.1 正常样本的异常检测校准

只用正常校准图像，可以控制同分布正常图像被误判为异常的概率。它不能证明缺陷不会被放行，也不能保证发现此前从未见过的缺陷。

### 3.2 按标签分组的 conformal 预测集合

模型分数 s 越高越异常。使用固定模型与独立校准集，分别定义：

```
p_normal(s) = (1 + #{正常校准分数 >= s}) / (n_normal + 1)
p_defect(s) = (1 + #{缺陷校准分数 <= s}) / (n_defect + 1)
C(s) = {0: p_normal > α_normal} ∪ {1: p_defect > α_defect}
```

并列分数全部计入，保守处理。C={0} 才允许放行，C={1} 报警，C={0,1} 或空集进入复核。缺陷校准样本为零时，p_defect 恒为 1，系统不能自动放行。

在标签内可交换、模型及评分函数独立于校准数据等假设下，缺陷标签被排除的概率不超过 α_defect；放行是排除缺陷标签的一个子事件。这里的保证是对校准集和未来样本随机性的预测覆盖结论，不是“当前固定阈值以 95% 置信度满足某风险”的等价说法，也不保证某一种新缺陷的召回率。

当 α_defect=0.01 时，至少需要 99 个缺陷校准样本，最小离散 p 值才可能达到 0.01。少样本时扩大预测集合、增加人工复核是合理结果。

### 3.3 独立风险验证

在预先冻结策略后，用另一个独立 validation 集计算漏检比例的 Clopper–Pearson 95% 单侧上界。只有上界≤ε，首版才开启自动放行。零漏检时，上界为 `1 - 0.05**(1/n)`；ε=1% 至少需要 299 个独立缺陷样本。

不能反复调参直到同一验证集通过，再把它当作单次 95% 保证。多候选比较必须预先规定次数并校正，或保留一次性最终验收集。当前自适应候选版本默认关闭自动放行，要求 fresh calibration / validation。

ECE 只对单独拟合的缺陷概率计算。Conformal p 值不当作缺陷概率使用。

## 4. 数据协议与泄漏控制

使用 CSV manifest 显式指定所有图片的用途：

| 划分 | 用途 | 可否进入正常记忆库 |
|---|---|---|
| train | 正常图像训练 | 可以，仅正常 |
| prob_fit | 分数到概率的拟合；深度模型调试必须另行披露 | 不可以 |
| calibration | 计算按标签分组的 p 值 | 不可以 |
| validation | 固定策略风险验收 | 不可以 |
| test | 最终报告 | 不可以 |
| pool | 待标注池；离线仿真可保存 oracle 标签 | 标注为正常后才可以 |

同一物理工件、连拍序列、生产批次及其增强版本必须用相同 group，并放在同一划分。代码检查重复 ID、相同文件路径、跨集合相同文件内容和 group 泄漏。不能自动识别语义近重复，真实数据仍需补齐批次与工件元数据。

校准尽可能按产品类别单独进行；不能把所有产品混合校准后声称每个产品都获得相同风险保证。原型每个运行目录对应一个产品类别，未知类别强制复核。

MVTec AD 和 VisA 的官方异常样本主要在测试划分中。本项目最终采用两个协议：`official` 保留全部官方正常训练图与全部官方测试图，用于主检测评测；`routing` 仅在官方训练部分继续划分校准/验收。任何模式都不消耗官方测试图做校准。对于训练无缺陷的数据集，应另外提供独立缺陷校准图，或保留无法自动放行的结论，不能借用测试缺陷。

建议真实小数据先拍 100–300 张验证流程、成像质量及标注规范。这个规模通常不足以支撑每类别 99% 召回的统计验收；需另外收集足够且具有代表性的缺陷样本。

## 6. 模型与系统设计

```
图片 + 产品类别
  → CPU patch memory / 可选真实深度模型
  → 异常分数、热力图、图像特征
  → 独立概率拟合 + 标签条件 conformal
  → 类别检查、图像统计漂移检查、风险验收
  → 放行 / 报警 / 复核（含约 5% 的自动决策随机抽检）
  → SQLite 复核记录与人工标签
  → 随机 / 不确定性 / coreset 选样
  → 候选模型 → 新独立校准与验收 → 人工切换版本
```

CPU 首版使用 RGB 局部均值、标准差、纹理梯度、贪心 k-center 记忆库及最近邻异常分数。它是用于工程闭环的简化基线，不是论文 PatchCore，也不使用预训练骨干。

正式研究基线使用 [Anomalib 官方实现](https://github.com/open-edge-platform/anomalib)。仓库提供可选 PatchCore / EfficientAD 训练入口。该入口只用 train 与 prob_fit 做训练和调试，保留 calibration、validation、test；此环境尚未训练这些深度模型，也尚未把其 ONNX 输出接入默认 CPU 服务。

有监督 U-Net/YOLO 对照、二级集成和 VLM 属于下一阶段。首版缺陷描述是热力图的确定性摘要。VLM 接入后只提供辅助描述，不改变自动放行策略，记录来源，禁止把生成文本当成真实标签。

漂移检查当前为图像亮度、标准差和饱和像素比例的简单守门规则，只能发现部分偏移。未触发不代表没有漂移。新缺陷召回不能靠这一检查保证。

## 7. 主动学习与模型生命周期

线上每张图像都有内容指纹与模型版本，重复提交保持幂等。所有推理结论持久化。反馈使用 revision 乐观并发控制，修正留下追加记录，避免两位标注人互相覆盖。

三种 acquisition 策略使用相同预算及种子：随机、不确定性（两个 conformal p 值的重叠程度）、标准化图像特征的 k-center。选择函数不读取标签。离线 oracle 只在选完后揭示 pool 标签，不能拿 test 标签做 acquisition。

正常反馈用于更新记忆库，另一部分反馈用于概率拟合；缺陷不能进入正常记忆库。当前单类检测器不利用缺陷反馈训练分割头。离线主动学习曲线明确报告“发现缺陷数”和“实际用于记忆库的正常数”，不承诺主动学习必然提升性能。

因为 acquisition 会依赖原校准数据，模型更新后复用它会破坏独立性。因此 `retrain` 只生成候选版本且关闭放行；`recalibrate` 固定候选模型，用与历史实验和反馈图像不重叠的全新校准及验证图像重新验收。代码可检测内容重叠，但新数据是否具有独立代表性仍由采样流程保证。

首版采用小记忆库批量重建，不宣传为无成本的在线增量深度学习。旧目录保持不变，重启服务选择旧目录即可回滚。

## 8. 实验矩阵与报告要求

| 维度 | 必做对照 | 报告 |
|---|---|---|
| 路由 | 固定阈值、双阈值、标签条件 conformal | 复核率—自动放行漏检率、置信上界、类条件覆盖率 |
| 主动学习 | random / uncertainty / coreset；多个固定种子 | 新标注预算、初始校准成本、恢复目标预算、方差 |
| 鲁棒性 | 亮度、模糊、噪声、旋转 | AUROC、复核率、漏检率、漂移触发率；保持模型与阈值冻结 |
| 新产品 | 一个类别完全不参与原模型训练，逐步增加正常训练样本 | 含校准/验收成本的总标签数；选择预算只用验证集 |
| 定位 | Image/Pixel AUROC、AUPRO@0.30 | 原始分辨率/缩放方式、掩膜缺失数、区域连通定义 |
| 系统 | CPU batch=1、预热后 p50/p95、PyTorch 与 ORT | 测量边界、线程数、模型大小、串行吞吐；GPU 显存留空 |

本地 AUPRO 使用 4 连通区域与离散阈值网格近似，字段明确标注 `_approx`；论文正式比较应与官方工具统一实现。正常图像没有掩膜时补全零掩膜，缺陷缺失掩膜时不编造定位标签。

对测试集画多策略曲线属于描述性分析，不能基于最好的测试点上线。任何增强、自适应阈值或新特征选择都要在训练/开发数据上完成，测试只做最后评估。

## 9. 建议的四阶段执行

1. 工程闭环：本次实现，跑通本地 demo、服务、标注与重新校准。
2. 真实基线：选择 MVTec 3–5 类及 VisA 2–3 类，训练真 PatchCore / EfficientAD，固定数据清单与权重，补接统一推理接口。
3. 核心研究：预注册路由参数与标注预算，至少 3 个种子，开展漂移、新类别、监督对照与人力成本实验。
4. 真实样机：固定相机、光源与工装，双人复核部分样本，测采集到决策的端到端延迟，积累独立验收数据。

验收不能只检查 AUROC 高：还应能复现全部清单、预算、校准样本量、独立风险上界、失败样例，以及一次候选回滚。
